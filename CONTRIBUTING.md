# Как помочь

Проект в стадии разработки и тестирования. Панель — самый доступный для
тестирования кусок экосистемы: exe ставится на обычный Windows-ПК, и прогнать
сценарии может любой, без разработки.

## Самый нужный вклад — тестирование

1. Скачать `Lucrium.exe` с [GitHub Releases](https://github.com/nechel12/lucrium-panel/releases),
   поднять воркер на чистом VPS (инструкция в
   [`lucrium-worker`](https://github.com/nechel12/lucrium-worker)) и пройти
   экраны: подключение → дашборд → аккаунты → лента событий → лоты → плагины →
   журнал → настройки.
2. Отдельно ценны прогоны на Windows-окружениях, где панель обычно и живёт:
   разные версии, SmartScreen и реакции антивируса на неподписанный exe,
   закрытые порты, прокси, шрифт/разречение экрана, длинные никнеймы и
   сообщения покупателей с RTL-текстом.
3. Проверка путей отказа: воркер недоступен, воркер перезапустился во время
   действия, невалидная JSON Schema у плагина, лишние поля в ответе, очень
   быстрая лента событий. Белый экран или зависший UI после этого — баг.
4. Формы настроек из чужих схем: установить плагин с необычной схемой и
   посмотреть, что рендерится. Всё, что роняет экран, — находка.

**Тестовые учётные записи площадок.** Панель управляет реальными сессиями
продавца: ошибки этой версии могут стоить банa, поэтому рабочие магазины
подключать не стоит.

## Как сообщать о проблеме

Нужны: версия панели и версия воркера (обе видны в логе воркера), шаг за
шагом, что ожидалось и что получилось, скриншот и текст ошибки. Логи панели
(`panel.log` в каталоге профиля) присылаются после проверки: **pairing-токена
и кредит площадок в них быть не должно** — если они там всё-таки видны, это
отдельная находка по безопасности, и сообщать о ней нужно приватно, как
описано в [SECURITY.md](SECURITY.md).

## Если правите код

```bash
uv sync
uv run ruff check .
uv run ruff format --check .
uv run mypy src      # strict
uv run pytest        # filterwarnings = error

cd frontend
npm ci
npm run build        # tsc --noEmit + vite build
```

- Ветки: `main`, история линейная, PR ведётся на rebase; CI обязан быть зелёным.
- Модели протокола не дублируются: всё общее берётся из
  [`lucrium-protocol`](https://github.com/nechel12/lucrium-protocol), там же
  меняется контракт.
- Данные от воркера и плагинов считаются недоверенными: новые экраны не должны
  рендерить HTML из ответов и обязаны переживать незнакомые поля (см.
  `components/ErrorBoundary.tsx` и рантайм-проверки в `SchemaForm.tsx`).
- Локальный API остаётся loopback-only с проверками Host/Origin/CSRF и
  одноразовым access-токеном: новые маршруты обязаны попадать под `LocalSecurityMiddleware`.

## Чего пока не нужно

Автообновления exe и интеграции с будущим магазином плагинов: это спланировано
отдельными этапами, параллельные реализации мешают. Для обсуждения направления —
сначала issue.
